## 2026-11-09 - Project Path Traversal Bypass and Error Info Leak Prevention on Web Endpoints
**Vulnerability:** In `POST /api/integrate`, when `target == "project"`, omitting or sending an empty `project_path` bypassed all boundary checks (`if target == "project" and project_path:` evaluated to false), causing the service to deploy commands and symlinks outside authorized project boundaries into `Path.cwd()`. Furthermore, null bytes (`\0`) in `project_path` were not rejected prior to filesystem resolution, triggering unhandled server exceptions, and `GET /api/models` exposed internal absolute server paths upon catalog load errors without message sanitization.
**Learning:** When endpoint validation checks are conditioned on both mode and an optional parameter (`if mode and param:`), callers can bypass validation by omitting the parameter while selecting the privileged mode. Mandatory mode parameters must be explicitly enforced before path processing, null bytes must be checked alongside directory traversal markers, and all exception responses must pass through centralized path sanitization.
**Prevention:** Always enforce required parameters per target mode (`if target == "project": if not project_path: error()`), reject both `..` and `\0` before constructing `Path` objects, align service fallbacks with the service root rather than `cwd()`, and sanitize all HTTP error responses with `_sanitize_message`.

## 2026-11-05 - API Key Masking Entropy Preservation and Leak Prevention
**Vulnerability:** The credential detector masking utility `mask_key` displayed visible prefixes and suffixes (2 prefix + 2 suffix, or 4 prefix + 4 suffix) across relatively short token lengths (e.g. 7-13 characters), disclosing over 55-60% of character entropy and simplifying brute-force or key-reconstruction attacks if exposed in logs or web status endpoints (`GET /api/providers`).
**Learning:** Masking functions must scale thresholds conservatively with token entropy. Short keys (< 8 characters) must be completely masked (`****`), intermediate tokens (8 to 16 characters) should expose at most 2 characters at each end, and only keys strictly longer than 16 characters should expose 4 characters.
**Prevention:** Always maintain a minimum required token length before revealing key fragments, and ensure unit tests explicitly assert privacy thresholds across length boundaries (<8, 8-16, >16).

## 2026-11-03 - Target Filename Whitelisting and Sensitive File Leak/Overwrite Prevention on Export and Diff Endpoints
**Vulnerability:** The HTTP API endpoints `POST /api/diff` and `POST /api/export` only enforced directory containment within `project_root` or `~/.config/opencode/`, but lacked target filename validation. An caller could target arbitrary sensitive files (e.g., `.env`, `data/provider_access.json`, `~/.config/opencode/auth.json`) or source files, leading to credential leaks via the unified diff returned in `/api/diff`, or destructive overwrite of codebase files and credential stores via `/api/export`.
**Learning:** Directory-boundary containment (`relative_to`) is necessary but insufficient when an endpoint reads or writes file content. Path validation for domain-specific exporters must enforce exact target filename whitelisting (`opencode.json`, `opencode.jsonc`) and reject directories or unrelated files.
**Prevention:** Centralize path validation in a shared method (`_validate_export_path`) verifying containment within approved directories, rejecting directories (`is_dir()`), and strictly constraining target filenames to `opencode.json` and `opencode.jsonc`.

## 2026-11-01 - Path Traversal Prevention on Web Integration Endpoints
**Vulnerability:** The HTTP API endpoint `POST /api/integrate` accepted unvalidated `target` and `project_path` payload values, creating directory traversal risk and arbitrary file write / symlink creation outside authorized project boundaries.
**Learning:** When new API endpoints are added that invoke service operations handling filesystem paths, endpoint-level input validation must mirror or exceed filesystem boundary constraints previously established in endpoints like `/api/export` and `/api/diff`.
**Prevention:** Strictly validate input arguments against whitelists (e.g., target names), explicitly reject path traversal markers (`..`), and enforce relative-to containment against the project root before passing filesystem paths to execution services.
